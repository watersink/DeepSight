# 煤安平台数据推送接口 —— 使用说明

推送目标：`http://192.168.26.224:8000/coal`（网关），认证方式 OAuth2 `client_token`（scope=`mine`）。

## 0. 前置条件

```bash
# ① 配置凭证（DeepSight/.env 已配好，换环境时改这里）
COAL_OAUTH_TOKEN_URL=http://192.168.26.224:8000/coal/oauth2/client_token
COAL_OAUTH_CLIENT_ID=<client_id>
COAL_OAUTH_CLIENT_SECRET=<client_secret>
COAL_OAUTH_SCOPE=mine
MINE_CODE=<12位煤矿编码>          # mineCode 兜底值

# ② 必须用装了 sqlalchemy / minio 的解释器（本机是 /usr/bin/python3）
#    miniconda 的 python 缺这两个包，会跳过摄像仪校验和图片上传

# ③ 必须在 DeepSight 目录下执行（.env 按当前工作目录加载）
cd /home/zhaoyu/mine/DeepSight
```

自检凭证是否可用：

```bash
/usr/bin/python3 -c "import sys;sys.path.insert(0,'.');from app.auth.client_token import get_client_token;print(get_client_token())"
# 输出 Bearer xxxxx 即正常
```

## 1. 六个接口一览

| 文档 | 接口 | 服务模块 | 入口函数 |
|---|---|---|---|
| 4 | `POST /mine/ai/camera` | `coal_camera_push` | `push_camera_config(camera)` |
| 5 | `POST /mine/ai/cameraStatus` | `coal_camera_status_push` | `push_camera_statuses(records)` |
| 6 | `POST /mine/ai/videoAnomaly` | `coal_video_anomaly_push` | `push_video_anomaly_records(records)` |
| 7 | `POST /mine/ai/countingRecog` | `coal_counting_recog_push` | `push_counting_recog_records(records)` |
| 8 | `POST /mine/ai/undergroundCount` | `coal_underground_count_push` | `push_underground_count_records(records)` |
| 9 | `POST /mine/ai/importPersonCount` | `coal_import_person_count_push` | `push_import_person_count_records(records)` |

统一特征：**请求体都是 JSON 数组**（一次可推多条）；失败只记日志、返回 `None`，不抛异常。
返回结构统一为 `{"code":200,"msg":"操作成功","pushed":n,"skipped":k,...}`。

## 2. 命令行（测试用脚本）

### 2.1 视频质量异常（文档 6）

脚本：`scripts/push_video_anomaly_test.py`

| 参数 | 说明 |
|---|---|
| `--camera-code` | 摄像仪编码，默认 `34020000001320000001` |
| `--analysis-case` | `0001`遮挡 `0002`挪动 `0003`过暗 `0004`过曝 `0005`模糊 `0006`冻结 `0007`丢失 `0008`抖动 `0009`分辨率异常 |
| `--data-time` | 默认当前时间 |
| `--mine-code` | 默认取配置兜底 |
| `--image` | 证据图片路径（默认用 `test_images_videos/video_anomaly_blocked_demo.png`） |
| `--no-image` | 不带图片，`localFiles` 为 `[]` |
| `--dry-run` | 只打印请求体 |
| `--skip-camera-check` | 跳过摄像仪有效性校验 |

```bash
/usr/bin/python3 scripts/push_video_anomaly_test.py                          # 画面遮挡 + 证据图
/usr/bin/python3 scripts/push_video_anomaly_test.py --analysis-case 0003      # 画面过暗
/usr/bin/python3 scripts/push_video_anomaly_test.py --analysis-case 0007 --no-image   # 视频丢失（无图）
/usr/bin/python3 scripts/push_video_anomaly_test.py --dry-run                 # 只看报文
```

### 2.2 摄像仪状态（文档 5）

脚本：`scripts/push_camera_status_test.py`

| 参数 | 说明 |
|---|---|
| `--all` | **采集本机全部摄像仪在线状态并推送**（从 ZLM 判在线，推荐用于定时任务） |
| `--camera-code CODE[=0\|1]` | 指定摄像仪，可带 `=0/=1`；可重复传多次 |
| `--status` | 统一状态 `1`=在线 `0`=离线 |
| `--dry-run` / `--skip-camera-check` | 同上 |

```bash
/usr/bin/python3 scripts/push_camera_status_test.py --all                     # 全量采集推送
/usr/bin/python3 scripts/push_camera_status_test.py --camera-code 34020000001320000005 --status 1
/usr/bin/python3 scripts/push_camera_status_test.py \
    --camera-code 34020000001320000001=0 --camera-code 34020000001320000005=1   # 多台一次推
/usr/bin/python3 scripts/push_camera_status_test.py --all --dry-run
```

### 2.3 人员计数 / 井下人数 / 运输设备人数（文档 7/8/9）

脚本：`scripts/push_person_count_test.py`，三个子命令：`counting` / `underground` / `transport`

公共参数：`--camera-code` `--person-count` `--data-time` `--mine-code` `--dry-run` `--skip-camera-check` `--list4` `--camera-codes`

```bash
# ① 人员计数识别 countingRecog
/usr/bin/python3 scripts/push_person_count_test.py counting \
    --camera-code 34020000001320000001 --analysis-type 06 --person-count 3
/usr/bin/python3 scripts/push_person_count_test.py counting --analysis-case 0002 --no-image
#   --analysis-type: 04非常规入井 05非常规出井 06入井闸机出闸 07出井闸机入闸 08胶轮车上下车
#   --person-count 3  → 自动补零为 analysisCase="0003"

# ② 井下人数不符 undergroundCount
/usr/bin/python3 scripts/push_person_count_test.py underground --person-count 25
/usr/bin/python3 scripts/push_person_count_test.py underground --analysis-case 0025

# ③ 重要运输设备实时人数 importPersonCount
/usr/bin/python3 scripts/push_person_count_test.py transport \
    --position-code 12345678901234 --position-name "斜井（架空乘人）" \
    --camera-code 34020000001320000001 --direction 01 --person-count 10
#   --direction: 01=入井 02=出井；--both-directions 同请求推入井+出井两条

# ④ 一次请求推 4 条（列表形式）
/usr/bin/python3 scripts/push_person_count_test.py counting    --list4
/usr/bin/python3 scripts/push_person_count_test.py underground --list4
/usr/bin/python3 scripts/push_person_count_test.py transport   --list4

    camera_code="34020000001320000001",
    analysis_case="0001",                    # 0001~0009
    data_time="2026-09-23 10:00:00",         # 省略则取当前时间
    images_base64=[frame_b64],               # 省略则跳过图片，localFiles=[]
)

# 摄像仪状态

push_counting_recog(

    analysis_type="04",                      # 04/05/06/07/08

push_underground_count(camera_code="34020000001320000001", person_count=25)

push_import_person_count_records([
    {"positionName": "斜井（架空乘人）", "positionCode": "12345678901234",

     "dataTime": "2026-09-23 10:00:00", "imagesBase64": [b64_a]},

     "dataTime": "2026-09-23 10:00:05", "imagesBase64": [b64_b]},

push_counting_recog_records([

    {"cameraCode": "34020000001320000001", "analysisType": "05", "analysisCase": "0001", "imagesBase64": [b64]},

```

| cameraStatus | `cameraCode` `cameraStatus`(0/1) `dataTime` `mineCode` |

## 4. 图片处理规则（文档 6.3 / 7.3）

- `imagesBase64` 为空 → 跳过上传，`localFiles` 为 `[]`；
- 单张支持**纯 Base64** 或 **`data:image/xxx;base64,`** 前缀，两者都行；
- 图片解码后上传 MinIO，返回的 URL 以 JSON 数组写入 `localFiles`；
- **单张失败只丢该张**，不影响本条记录入库与整体推送；
- 支持 jpg / png / gif / webp / bmp / tiff（按 magic number 自动识别，不信任声明）；
- 单张上限 20MB，超出跳过并告警；
- 对象名格式：`{前缀}/{cameraCode}/{yyyyMMdd}/{HHmmssffffff}-{uuid8}.{ext}`
  前缀：视频异常 `coal/video_anomaly`、人员计数 `coal/counting_recog`。

## 5. 排查速查

| 现象 | 原因 / 处理 |
|---|---|
| `无法连接 ... No route to host` | 煤安平台网络不通（VPN/网络切换/平台停机），与代码无关 |
| `COAL_OAUTH_CLIENT_ID / _SECRET 未配置` | `.env` 未填凭证，或不在 `DeepSight` 目录下执行 |
| `未查询到该客户端信息` | client_id / client_secret 不对，或保留着占位文字 |
| `跳过一条...cameraCode=xxx 不在摄像仪基本信息中` | 摄像仪编码不在 `mgmt_cameras` 表里，先把该摄像仪推送到 `/mine/ai/camera` |
| `文件服务不可用（minio SDK 未安装）` | 用错解释器了，换 `/usr/bin/python3` |
| `读取摄像仪基本信息失败，跳过 cameraCode 校验` | 同上，缺 sqlalchemy；此时不校验但**仍会推送** |
| 平台返回 `code=500` | 看日志里的 `msg`，通常是参数校验失败（如摄像仪编码为空） |
| 想先看报文不推送 | 三个脚本都支持 `--dry-run` |

## 6. 状态推送的 mineCode 注意点

`cameraStatus` 的 `mineCode` 取**每台摄像仪自己的 `mine_code`**（不是全局兜底），
以保证与 `/mine/ai/camera` 推送的 `mineCode` 一致——否则同一台摄像仪在平台的
"基本信息"和"状态"会挂到不同煤矿下。用 `push_camera_statuses` 手拼记录时，
如果想让某台走全局兜底，就不要传 `mineCode` 字段。
